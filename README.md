# Voucher Management

سند قبض / صرف / تحويل داخلي **متعدد الأطراف** لـ ERPNext.

`Payment Entry` القياسي يقبل طرفاً واحداً لكل مستند. هذا التطبيق يقبل جدول حسابات
متعدد الصفوف — لكل صف حسابه وطرفه ومركز تكلفته ومشروعه وقالبه الضريبي وعملته — ويرحّل
كل ذلك إلى `GL Entry` في قيد واحد.

---

## التثبيت

```bash
cd $PATH_TO_YOUR_BENCH
bench get-app <repo-url>
bench --site <site> install-app voucher_management
bench --site <site> migrate
bench restart
```

`migrate` يشغّل ثلاثة patches تلقائياً:

| Patch | الوظيفة |
|---|---|
| `enable_dimension_allow_on_submit` | يفعّل تعديل الأبعاد المحاسبية بعد الترحيل |
| `rename_suppiler_to_supplier` | يصحّح خطأً إملائياً في اسم حقل وينقل بياناته |
| `backfill_exchange_rates` | يضع سعر صرف `1` للسندات القائمة — لا يعيد ترحيل أي قيد |

الثلاثة **idempotent**: تشغيل `migrate` مرة أخرى لا يكرر شيئاً.

## الإعداد قبل الاستخدام

### ١. الأساسيات

| الإعداد | أين | لماذا |
|---|---|---|
| الصلاحيات | Role → `Accounts User` / `Accounts Manager` | من ينشئ ويرحّل السندات |
| حساب التقريب | Company → Round Off Account | مطلوب من ERPNext لأي قيد |
| السنة المالية | Fiscal Year | السند يُرفض إن كان تاريخه خارجها |

### ٢. تفعيل التعامل بالعملات

بدون هذه الخطوات يعمل التطبيق بعملة الشركة فقط، ويرفض أي حساب بعملة أخرى برسالة واضحة.

**أ. حساب فروق العملة** — إلزامي

```
Company → Exchange Gain / Loss Account
```

حساب مصروف أو دخل. أي فارق بين سعر الفاتورة وسعر السند يُرحَّل إليه. بدونه يُرفض أي سند
يحتوي عملة أجنبية.

**ب. أسعار الصرف**

```
Currency Exchange → New
    From Currency  : USD
    To Currency    : SAR        ← عملة الشركة
    Exchange Rate  : 3.75
    Date           : تاريخ السريان
```

سجل واحد لكل عملة يكفي. عملات الخليج مربوطة بالدولار بسعر ثابت، فلا يتغيّر السجل إلا إن
تغيّر الربط.

يُملأ السعر تلقائياً في كل سند من آخر سجل في تاريخ السند أو قبله، **ويبقى قابلاً
للتعديل**. لا يُجلب أي سعر من الإنترنت — السند المحاسبي لا يتوقف على اتصال شبكة.

> إن لم يوجد سجل، يُترك الحقل فارغاً ويُرفض السند برسالة تطلب إدخال السعر. **لا يُفترض
> السعر `1` أبداً** — هذا كان سيرحّل مبلغاً أجنبياً كأنه بعملة الشركة.

**ج. الحسابات بالعملة الأجنبية**

```
Account → New → Account Currency : USD
```

أنشئ ما تحتاجه: بنك بالدولار، ذمم مدينة بالدولار، ذمم دائنة بالدولار.

**د. عملة الأطراف**

```
Customer / Supplier → Accounting → Default Currency
```

**قيد مهم:** عملة صف الطرف يجب أن تطابق عملة فاتورته عند التخصيص. عميل بالدولار
تُخصَّص له فواتير بالدولار فقط.

**هـ. حسابات الضريبة**

تبقى **بعملة الشركة إلزاماً**. رأس ضريبة واحد يجمع صفوفاً بعملات مختلفة، فرصيده بعملة
أخرى بلا معنى. الضريبة تُحسب على الصف بعملته ثم تُحوَّل قبل الترحيل.

## الاستخدام

### أنواع السندات

| النوع | القيد |
|---|---|
| **Receive** | مدين: حساب الدفع · دائن: صفوف الأطراف + الضرائب |
| **Pay** | مدين: صفوف الأطراف + الضرائب · دائن: حساب الدفع |
| **Internal Transfer** | دائن: `paid_from` · مدين: `paid_to` |

### حين تختلف العملات

يظهر حقل **Payment Amount** — أدخل ما تحرّك في البنك فعلاً. لا يُشتق تلقائياً لأن الصفوف
قد تكون بعملة والبنك بأخرى.

الفارق بين طرفَي السند يُرحَّل إلى حساب فروق العملة كسطر واحد، وتظهر قيمته أعلى السند.

> **حد ١٪:** إن تجاوز الفارق ١٪ من قيمة السند يُرفض الترحيل. مع سعر مربوط ثابت، أي فجوة
> بهذا الحجم هي خطأ إدخال لا حركة سعر. لتعديل الحد:
> `EXCHANGE_DIFFERENCE_LIMIT` في `voucher_management/doctype/vouchers_entry/vouchers_entry.py`

### الضرائب

قوالب `Purchase Taxes and Charges Template`. المدعوم:

- `Actual` · `On Net Total` · `On Previous Row Amount` · `On Previous Row Total`
- `included_in_print_rate` — المبلغ المدخل يحتوي الضريبة فيُستخرج الصافي منه
- `add_deduct_tax = Deduct` — استقطاع، يُرحَّل على الجانب المقابل

غير مدعوم: `On Item Quantity` — يحتاج أصنافاً ولا يحتوي السند أصنافاً، فيُتخطّى بصمت.

لكل رأس حساب ضريبي سطر GL مستقل. قالبان مختلفان في صفّين ينتجان سطرين.

### تخصيص الفواتير

زر **Get Outstanding Invoices** يجلب الفواتير المستحقة للأطراف الموجودة في الجدول ويوزّع
المبالغ.

كل تخصيص يُرحَّل **مرة واحدة** ويُقسَّم على صفوف الطرف بقدر سعة كل صف. التخصيص الزائد
عن رصيد الطرف يُرفض عند الحفظ.

## الإقفال المحاسبي

يعمل تلقائياً بعد الإصلاحات، بلا كتابة سطر واحد:

```
Accounts Settings → Accounts Frozen Till Date
```

حرّك التاريخ بعد كل إقرار ضريبي. يُفحص عند **الحفظ** لا عند الترحيل فقط، ويشمل الإلغاء
والتعديل بعد الترحيل.

`Accounting Period` مدعومة أيضاً إن سُجّل `Vouchers Entry` ضمن مستنداتها المقفلة.

> راجع من يحمل دور `Frozen Accounts Modifier` — إن أُسند لكثيرين صار التجميد شكلياً.

---

## الإلغاء والتعديل

| العملية | السلوك |
|---|---|
| **إلغاء** | القيود تُعكَس ولا تُحذف (`is_cancelled = 1`)، ومستحق الفواتير يعود |
| **تعديل بعد الترحيل** | الحقول الوصفية فقط، وتُحدَّث سطور القيد موضعياً بلا حذف |
| **حذف** | مرفوض ما دامت للسند سطور دفتر |

الحقول القابلة للتعديل بعد الترحيل: `remarks` · `cost_center` · `project` ·
`user_remark` · الأبعاد المحاسبية.

المبالغ والحسابات والأطراف والتاريخ **تحتاج إلغاء + تعديل (Amend)**.

## أداة التشخيص

```bash
bench --site <site> execute voucher_management.diagnose.run
```

**قراءة فقط** — لا تنشئ ولا تعدّل شيئاً. سبعة فحوص:

| # | يفحص |
|---|---|
| 1–2 | الـ patches والـ hooks مُطبَّقة |
| 3 | ربط سطور القيد بصفوفها |
| 4 | توازن كل سند مرحَّل |
| 5 | **السندات المرحَّلة بقوالب ضريبة شاملة** |
| 6 | **السندات المعرَّضة لتكرار التخصيص** |
| 7 | سطور دفتر بلا سند |

القسمان ٥ و ٦ يُخرجان قائمة السندات التي رُحِّلت **قبل** الإصلاحات وتحمل أرقاماً خاطئة.
شغّلها بعد التحديث مباشرة.

## تصحيح السندات القديمة

الإصلاحات تحكم ما يُرحَّل من الآن فصاعداً. السندات السابقة تحتفظ بأرقامها في الأستاذ
العام — **لا يصححها التحديث تلقائياً**، لأن تصحيح دفتر مرحَّل قرار محاسبي لا تقني.

1. شغّل `diagnose.run` واحفظ القائمة
2. راجعها مع المحاسب
3. لكل سند: إلغاء ثم Amend — يُعاد تسعيره بالمعادلة الصحيحة

---

## حدود معروفة

- **تكرار الطرف في أكثر من صف**: التخصيص يُوزَّع بترتيب الصفوف. متوازن وحتمي، لكن اختيار
  الصف تعسّفي إن اختلفت مراكز التكلفة بين الصفين.
- **حسابات الضريبة** لا تقبل عملة أجنبية (بالتصميم).
- **`On Item Quantity`** غير مدعوم في القوالب.
- **العملات غير المربوطة** (يورو، جنيه): راجع حد الـ ١٪ — قد يكون ضيقاً على عملة متحركة.
